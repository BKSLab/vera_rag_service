## Проблема ключа в текущих настройках

[`RAG_SERVICE_API_KEY` в локальном `.env` MCP](C:/work/BKS.Lab/python/my_projects/vera_mcp_service/.env:17) отличается от [`API_KEY` в `.env` RAG](C:/work/BKS.Lab/python/my_projects/vera_rag_service/.env:28).

Проверено на RAG-адресе, указанном в настройках MCP. В обоих случаях отправлялся заведомо невалидный запрос `{"query":"","top_k":1}`, который не запускает поиск или внешние модели:

| Использованный ключ | Ответ |
| --- | --- |
| Из локального `.env` MCP | **HTTP 401** — ключ отклонён. |
| Из настроек RAG | **HTTP 422**, ошибка поля `body.query` — авторизация пройдена, сработала ожидаемая валидация пустого запроса. |

Перед запуском MCP с этим `.env` нужно согласовать `RAG_SERVICE_API_KEY` с принимаемым RAG ключом. Значения ключей в отчёт не включены; настройки не переписывались. Фактическое окружение уже развёрнутого MCP-процесса не читалось: по локальному файлу нельзя утверждать, что работающий процесс использует тот же ключ.

Полный поиск через развёрнутую цепочку с платными LLM/эмбеддингами не запускался. Вывод о совместимости изменений относится к текущему коду и выполненному локальному сквозному прогону; качество ответов после новой загрузки корпуса требует отдельной проверки на содержимом базы.
